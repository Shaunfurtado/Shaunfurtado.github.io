An agent answer about markets goes stale almost immediately. "Infosys is at 1,512, up 0.8%" is true when it's written and quietly wrong five minutes later, while the user is still reading the paragraph and deciding what to do.

We didn't want to re-run the agent to refresh a number, and we definitely didn't want the model streaming prices. So answers in Ananta can contain *live islands*: small chips inside otherwise static text that show the current price when one is available, and an honest snapshot when it isn't.

## A closed token, not free text

The agent doesn't get to decide what's live by writing a price in a sentence. It writes a token:

```text
{{ltp:NSE:INFY|ltp=1512.40|chgPct=0.81|asOf=2026-09-03T10:42:00+05:30}}
```

The grammar is closed. Exchange and symbol, then at most four attributes — `asOf`, `chgPct`, `kind`, `ltp` — and nothing else. Values containing quotes, angle brackets, or backticks are dropped, as is anything that looks like an `on*` handler. There's a cap of 24 islands per message.

We deliberately don't detect "INFY at 1512" in prose. Guessing which numbers are prices is how a strike price, a target, or last year's close starts ticking live next to a sentence that was about something else. If the agent wants a live number, it asks for one explicitly. Historical numbers stay plain text.

The backend normalises tokens before the answer is stored, including upgrading an older `{{quote:…}}` format, so the frontend only has to understand one.

## Getting through the sanitiser

Chat markdown is rendered with Streamdown, which sanitises the HTML. That's good — it strips unknown tags and rewrites custom URL schemes to `[blocked]`. It also meant that every clever way of smuggling a custom element through got eaten.

So we stopped smuggling. Before rendering, each token becomes an ordinary relative link:

```ts
// {{ltp:NSE:INFY|ltp=1512.40}}  ->  [INFY](/__ananta-ltp__/NSE/INFY?ltp=1512.40)
```

A relative link survives the sanitiser untouched. Our markdown link renderer recognises the `/__ananta-ltp__/` prefix and renders a `LiveLtpIsland` component instead of an anchor. React builds the DOM. The model never supplies any of it.

## One subscription per chat, not per chip

A research answer can easily have twenty islands, and a chat can have several answers. A socket per chip would be absurd.

Each chat has one `LivePriceIslandProvider`. Every island registers what it needs, and the provider merges those into a de-duplicated list keyed by `EXCHANGE:SYMBOL`, then opens a single live-price subscription for the chat. The flow:

- Every 30 seconds, and whenever the tab becomes visible again, the client posts its demand to an authenticated endpoint, scoped to the chat.
- It opens a WebSocket and must send a `subscribe` message naming the account, broker, and symbols within five seconds, or the server closes it.
- The server intersects the request with the user's actual subscriptions, then reads that user's Redis price streams and sends a snapshot first, then ticks.
- The client batches incoming ticks for 200 ms before re-rendering, so a busy market doesn't redraw the chat thirty times a second.

Chat run events use server-sent events. Prices use a WebSocket. That isn't inconsistency. Run events are a log: every event matters, they're numbered, and a reconnect resumes from the last sequence. Prices are latest-value: if you missed ten ticks, you want the eleventh, not a replay. Different data needs a different recovery story.

## Live, snapshot, or nothing

Each island shows one of three things:

```ts
const ltp = liveTick?.ltp ?? snapshot.ltp ?? null;
const isLive = liveTick?.ltp != null;
const asOf = isLive ? null : snapshot.asOf;
```

A live tick is shown in normal colour. Without one, the snapshot from the token is shown muted, with its "as of" time. With neither, an em dash. The accessible label reads as a sentence — "INFY 1,512.40 rupees, up 0.81%, live" — rather than a cluster of numbers.

Copying an answer copies the numbers *currently on screen*, flattened to text like `INFY 1512.40 (+0.81%)`, not the raw token. Live ticks are never fed back to the model. They're for the person reading.

## Islands inside canvases

Canvases built with the HTML kit run in a sandboxed iframe with an opaque origin. They can't open their own socket, and we wouldn't want them to. The parent page posts ticks to the iframe, and the kit's script inside only accepts a message if it came from its actual parent window:

```js
window.addEventListener("message", (e) => {
  if (e.source !== window.parent || e.data?.type !== "aw-ltp") return;
  repaint(e.data.ticks);   // keyed by EXCHANGE:SYMBOL
});
```

## What the real-browser test found

In mid-October we ran a positive and negative test of all this in a real sandboxed Chromium, and it found four bugs that unit tests hadn't:

1. **Wrong exchange, same symbol.** The tick cache was keyed by symbol only, so a BSE tick, or a tick from a different account, could overwrite an NSE observation the user had selected. Keys now include exchange and account.
2. **Any window could post ticks.** The canvas accepted price messages from any window, not just its parent. Now it checks `e.source`.
3. **Null became zero.** A missing price attribute rendered as `0.00`. For a price, that's not a harmless default — it looks like the stock collapsed. It's an em dash now.
4. **M&M.** Symbols with `&` in them fell outside the token grammar, and the raw token text leaked into the answer. The grammar now allows it.

A week later we found a quieter issue upstream. Our REST poller handles 100 symbols per batch. Active workflows were pinning about 213, sliced in an order that changed every 30 seconds — so some symbols weren't polled for minutes, and their islands and alerts went stale with nothing visibly wrong. Overflow now rotates in a stable order.

## What I'd still change

Ticks are merged last-write-wins, with missing fields filled in from the previous value. That's fine for one feed per symbol, and it's the next thing to tighten if we add a second. Reconnects wait a fixed 2.5 seconds rather than backing off. And an island doesn't yet mark itself stale if ticks stop arriving while the socket stays open. It just keeps showing the last live value. That's on the list, because the most important thing a live price can tell you is when it stopped being live.

The agent in Ananta can write and run Python. Analysts use it all the time: reshape a holdings export, compute rolling returns, plot a sector breakdown, turn a CSV the browser agent downloaded into a clean table. It's one of the most useful tools we ship, and it's the one I worry about most, because it runs code a language model wrote on a server that also holds a client's broker credentials.

This is how the sandbox is built today, and the things that went wrong on the way there.

## A separate service with nothing worth stealing

The sandbox is its own FastAPI service, the sandbox broker. The backend never runs model-written code itself. When the agent calls `sandbox_run_python`, the backend mints a short-lived HMAC grant — subject, expiry, nonce, a capability (`python.exec` or `workspace.write`), and the chat session key — with a two-minute TTL. The broker checks the signature, expiry, and capability before it does anything else.

One honest caveat: the broker doesn't keep a nonce table, so grants are short-lived, not single-use. Two minutes is the replay window. I'd rather say that plainly than imply a guarantee we don't enforce.

What the guest gets is just as important as what it doesn't. Guests never mount the application data volume, the browser profiles, or the artifact store. They never receive Redis credentials or the encryption key. The broker also has a hard list of mount prefixes it will refuse — `/data`, `/home`, `/root`, `/etc`, `/var/run/docker.sock`, and our own state directory — so a configuration mistake can't quietly hand the guest the host.

## The runtime is chosen by what the host can actually do

We don't control the client's hardware, so the broker picks the strongest runtime available and tells you which one it picked:

```python
def select_runtime(host) -> Runtime:
    if host.has_kvm and boxlite_ok():
        return Runtime("microvm", reason="BoxLite on /dev/kvm")
    if host.has_runsc:
        return Runtime("isolated-container", reason="gVisor runsc")
    if settings.SANDBOX_ALLOW_LOCAL_RUNTIME:
        return Runtime("docker-container", reason="local opt-in, dev only")
    return Runtime.unavailable("no isolating runtime on this host")
```

A BoxLite microVM when the host exposes `/dev/kvm`. Otherwise a gVisor container. Plain Docker only when an operator explicitly opts in, and the health check labels it `docker-container` so nobody mistakes it for isolation. If none of those exist, the tool is unavailable and the agent says so.

The container-level flags are the boring list you'd expect, and every one of them is there on purpose:

```python
client.containers.run(
    "python:slim",
    command=["sleep", "infinity"],
    network_mode="none",
    read_only=True,
    tmpfs={"/tmp": "size=64m"},
    cap_drop=["ALL"],
    security_opt=["no-new-privileges"],
    mem_limit="512m",
    nano_cpus=1_000_000_000,
    runtime="runsc",
)
```

Code runs through `exec` into that sleeping container. A timeout (30 seconds by default, 120 at most) kills the whole container with exit code 124, not just the process. The workspace survives because it lives outside the container.

## No network, and no exception path

Early drafts of this design had a "network profile" the agent could ask for. We dropped it. The guest has `network_mode: none` and there is no way to open it.

The agent still needs data, so the backend writes it in. When a tool returns a large result — a quote history, a fetched web page, a browser download — the harness materializes it as a file in the session's workspace under `/workspace/tools`, `/web`, or `/runs`, and keeps an `INDEX.json` the code can read. The model doesn't have to paste 40,000 rows into a code cell, and the sandbox never needs credentials to fetch anything.

Deliverables go in `/workspace/user/out`. The broker validates every path it hands back as a download, and as of October a path outside the allowed workspace raises an error instead of being skipped quietly.

## Capacity is a memory problem

On a client's single VPS, what runs out first is memory, not CPU and not container count. So admission is a formula, not a feeling:

```python
slots = int((mem_available / 1.2 - reserve_mib) / per_guest_mib)
# reserve_mib = 1024, per_guest_mib = 512
```

Two details matter more than the formula. Guests that are still starting count against capacity before their expensive startup finishes. Otherwise a burst of requests all pass admission and then all start at once. And existing guests are charged their full memory cap, not their current usage, because a guest that's idle now can allocate its full 512 MiB a second later.

On top of that there's a global ceiling of 16 boxes, one slot per user-and-session, and a 90-second idle TTL. When a session goes idle, the broker exports its workspace as a tarball to an ephemeral volume and frees the slot. The next request restores it.

## Bugs that taught me something

**"Local mode" used to be a subprocess.** Until September, the dev-only local runtime ran Python as a subprocess inside the broker itself. The comment said "not a security boundary", which was true and not reassuring. We rewrote it as a real container with no network and all capabilities dropped. Docker Desktop can't bind a named-volume subdirectory into a child container, so local mode keeps the workspace inside the container and moves files in and out through Docker's archive API. It's slower and it's correct.

**BoxLite without nested KVM panics.** On Docker Desktop, BoxLite would panic inside its own initialisation before our fallback logic got a chance to run. Now the fallback order never puts BoxLite ahead of a runtime that's already been selected. Upgrading to BoxLite 0.10 brought its own list: exec output has to be read from the streams rather than from `wait()`, setting the working directory fails if it doesn't exist yet, and on Ubuntu hosts with AppArmor the broker has to run privileged for bubblewrap to work.

That last point deserves to be said clearly. The broker is privileged and holds the Docker socket, so it's a high-trust component. The isolation is the guest boundary — the microVM or gVisor — not the broker. The broker's job is to be small and to refuse things.

**Write returned 200, read returned 404.** In mid-October an analyst imported a CSV the browser agent had downloaded. The import returned HTTP 200. Opening the file straight after returned 404.

BoxLite was writing its snapshot archive, `/workspace/.snapshot.tgz`, *inside the directory it was archiving*. GNU tar exited with status 1 — "file changed as we read it" — the pool swallowed the error, saved a stale copy of the host mirror, and acknowledged the import anyway.

The fix: archives go to unique paths in the guest's `/tmp`; a tar failure stays a failure; an import is only acknowledged after the host-side size and SHA-256 match what was written; and reads take the same session lock as writes. While we were in there we found that best-effort snapshot export had also dropped deliverables now and then, so `/user/out` is copied explicitly. A related change means a failed restore now says "retained workspace was preserved" instead of starting the user on an empty workspace.

## Calculators with receipts

The newest piece is extension functions. An operator can enable typed calculators — position sizing, a VWAP variant, a fee schedule — that show up inside the guest as `ananta.ext.<name>(...)`. Every call appends a line to `runs/extension_calls.jsonl` with the tool, version, input hash, output hash, and status. If a hard kill stops the run before that file is finalised, the result reports `extension_calls_complete=false` rather than pretending the log is whole.

The model can *propose* a new calculator: standard-library-only source, up to 20,000 characters, with 1 to 20 test fixtures. Passing the fixtures doesn't enable it. Only the owner, through an approval card, can turn on that exact evaluated version. No model, child run, or planning mode can do it on its own.

Those receipts are evidence of a calculation, not authorization and not a tamper-proof attestation. Being precise about that is a lot of what this work has turned out to be.

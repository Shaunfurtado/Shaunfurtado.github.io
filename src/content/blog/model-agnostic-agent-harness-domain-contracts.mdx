Our clients don't all want the same model. Some are happy with whatever OpenRouter routes to. Some want Anthropic. Some — especially anyone handling client portfolios under confidentiality rules — want certain content to stay on a model they host themselves. Ananta has to run the same agent, with the same tools and the same guarantees, across all three.

"Model-agnostic" is easy to claim and hard to mean. Here's what it means for us, and where we deliberately stopped.

## One wire format

Every provider goes through the `openai` SDK's Chat Completions shape, and the agent loop runs on the OpenAI Agents SDK. OpenRouter is the main path. Anthropic was added in May. Custom OpenAI-compatible endpoints — vLLM, an internal gateway, anything that speaks the protocol — were added in October.

Not every compatible endpoint can stream, so there's a small adapter that turns a non-streaming response into synthetic stream events. The rest of the harness doesn't need to know.

That's the easy 20%. The rest is about what the wire format *doesn't* tell you.

## Each model declares what it can do

Every configured model has a capability record:

```python
class ModelCapabilities(BaseModel):
    context_window: int = 32_768
    supports_tools: bool
    supports_streaming: bool
    supports_vision: bool
```

Before any request is sent, a dispatch gate checks it against that record and the workspace's policy. It refuses — with a message a person can act on — if the request has tools and the model doesn't support them, asks for streaming the endpoint can't do, includes images for a non-vision model, exceeds the context window once reserved output is counted, uses a provider or model that isn't on the allowlist, sends confidential content to an endpoint that isn't self-hosted, or uses third-party inference when the workspace has turned it off. If the endpoint configuration changes in the middle of a run, the run stops and asks for a new one.

```python
if body.get("tools") and not caps.supports_tools:
    raise InferencePolicyRefusal("This model does not support tools.")
if estimate_tokens(body) + max_output > caps.context_window:
    raise InferencePolicyRefusal("This request exceeds the model's context window.")
if run.confidential and not endpoint.self_hosted:
    raise InferencePolicyRefusal(confidential_refusal(endpoint))
```

The important word is *refuses*. There's no silent fallback to another model. If a confidential run can't go to the self-hosted endpoint because it's down, it doesn't quietly go to the cloud. And a model that can't do tools isn't handed a degraded, tool-less version of the agent as though that were the same product.

## Confidentiality follows the content

A run becomes confidential because of what it *retrieved*, not what it's called. Once confidential content is in a run, the label follows it into follow-ups, summaries, child runs, and canvases. Names, counts, and empty search results don't make a run confidential. That stickiness is why the compaction summariser has to pass the same policy check as the chat model — otherwise summarising would be a way to launder confidential text to a cheaper cloud model.

"Self-hosted" is something an admin declares about an endpoint. It isn't network attestation, and the docs say so. A private proxy in front of a cloud model is third-party inference, whatever its hostname. Custom endpoints have their own rules: external endpoints must use HTTPS; plain HTTP and private addresses are only allowed for endpoints declared self-hosted; cloud metadata and link-local addresses are blocked, including when they're hidden inside an IPv6 address; the resolved address is checked before TLS; redirects aren't followed; and changing an endpoint's origin means entering the API key again.

## Token counts without a tokeniser

We can't load a tokeniser for every model a client might plug in. So we estimate at three bytes per token — four is typical, and three leaves a 33% margin — and use that *same* estimate everywhere: admission, packing history, and the dispatch gate. If the three disagreed, a request could pass admission and then fail at dispatch.

That estimate drives a real product decision. The full tool catalogue plus instructions is about 50,500 estimated tokens. A model with a 64k window is the minimum we'd call comfortable, and 128k is preferred. A 32k model gets a reduced catalogue and loads further tools on demand, eight at a time. It works, but it's a different, slower agent, and we tell the admin that rather than pretend otherwise.

## The harness owns retries and quirks

The provider SDK runs with `max_retries=0`. Our retry policy classifies failures — transient transport, rate limited, quota exhausted, unknown tool, repeated tool call, unpaired tool results, unsupported parameter, policy refused — and treats each differently: 2-second base delay, 12-second maximum, a 60-second cap on any delay the server asks for, and a 75-second limit on an idle stream. That came from an SDK honouring an hours-long `Retry-After` inside a job with a ten-minute timeout.

Model quirks are handled in code, not in prompts. Some models write tool calls as JSON in their reply text instead of making a real call, so for canvas tools there's a recovery path that detects and executes those. Planning-only mode is enforced by wrapping the tools so they refuse, not by asking the model nicely. A truncated completion is recorded from the wire receipt and either continued or marked incomplete.

## Domain rules live in typed modules

The model can vary. The rules about money can't. So they don't live in the prompt.

```python
class FinanceMetricBinding(BaseModel):
    symbol: str
    scope: Literal["standalone", "consolidated"]
    period: str
    metric: Literal["revenue", "pat", "eps", "operating_profit"]
    unit: str
    multiplier: Literal[1, 4] = 1   # 4 only for hypothetical calculator EPS
```

Standalone and consolidated figures are never mixed. Annualising quarterly EPS by four is allowed only in a hypothetical calculator, and it's disclosed as an assumption. A cited source has to be a URL the run actually retrieved or a receipt for a tool event the run owns. The research delivery gate holds back a report with named reasons when coverage, freshness, or pagination can't be verified. All of that is code that any model's output passes through. When we switch models, none of it changes.

Typed extensions work the same way. A calculator extension declares one host capability, sandbox execution, with a pinned implementation file. The API process never imports extension code. An extension only attaches if it's enabled *and* passed its fixture evaluation. If the sandbox isn't healthy, extension tools disappear rather than fail halfway.

## Where we stopped, honestly

Two things I want to be clear about.

First, the self-hosted endpoint path was merged in late October without a live test against a real self-hosted model. That was a deliberate owner decision; what we tested is a synthetic OpenAI-compatible server that behaves like one. I'm not going to claim it's proven with vLLM or Ollama until it is.

Second, search. In October DuckDuckGo began answering our server with a bot challenge. The harness escalated to the browser session, which was stale, and agents went round in retry loops. We added commercial search APIs, removed them the same day after discussion, and settled on a keyless metasearch package pinned to an exact version. Not every dependency is a model, but the rule is the same: pin it, check what it actually returned, and refuse clearly when it can't do the job.

Model-agnostic, for us, doesn't mean any model gives the same result. It means any model gets the same contract — the same refusals, the same evidence rules, the same domain checks — and when one can't meet it, the system says so instead of degrading quietly.
